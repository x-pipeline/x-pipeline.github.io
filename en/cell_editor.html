    Custom Cell Input¶

    Custom columns in the main view can use different input controls based on their data type. When multiple rows are selected, the same column can also be changed to one value in a single operation.

    Edit Multiple Rows¶

    1. Hold Ctrl or Shift and select multiple rows.
    2. A ... hint appears at the right edge of the current cell.
    3. Click ...; the menu shows how many rows are selected.
    4. Choose "Batch edit current column..." and enter or choose a value.
    5. On commit, every editable selected row in that column receives the same value.

    Tip

    ... only appears in the current cell, and clicking it does not clear the other selected rows. Rows outside the selection are not changed.

    Controls by Data Type¶

    data_type Input control Result
    list Drop-down using value_list String
    float / double Floating-point spin box Number
    int / integer Integer spin box Integer
    datetime Date-time editor with calendar popup yyyy-MM-dd HH:mm:ss
    date Date editor with calendar popup yyyy-MM-dd
    time Time editor HH:mm:ss
    Other or unconfigured Original itemDelegate Existing behavior

    For visibility, column identifiers, and Python-computed columns, see Header Column Configuration.

    Cell Rendering render_type¶

    data_type selects the editor opened on double-click, while render_type controls how the cell is displayed at rest. They are configured independently.

    render_type Rendering
    progressbar Progress bar
    button Button style
    Missing or unregistered Original itemDelegate painting

    Limit Render Height¶

    Both progress bars and buttons support max_height. When the row is taller, the rendered control is capped at max_height and vertically centered. Shorter rows continue to use the available cell height. The parameter affects only the rendered control; it does not change the row height.

    {
  "data_type": "float",
  "render_type": "progressbar",
  "max_height": 32
}

    Progress Bar¶

    {
  "data_type": "float",
  "render_type": "progressbar",
  "min": 0,
  "max": 100,
  "suffix": "%",
  "max_height": 32,
  "show_percent_value": 0,
  "color": [[1, 0, 0], [0, 1, 0]]
}
    • min / max default to 0 / 100; values are clamped to that range.
    • suffix is appended to the displayed value.
    • text_format can be a format string such as "{value:.1f}%".
    • Set show_text to false to hide the value.
    • color accepts 0–1 RGB such as [0, 1, 0] or 0–255 RGB such as [0, 255, 0].
    • When color contains two colors, the first is used at 0% and the second at 100%. Intermediate progress is linearly interpolated across RGB/RGBA channels, for example [[1, 0, 0], [0, 1, 0]] or ["#ff0000", "#00ff00"].
    • show_percent_value affects the progress text only. The default is 0, which shows the real data value. Set it to 1 to show the percentage calculated from min / max, regardless of max.
    • When show_percent_value=1, the default percentage suffix is % unless suffix is explicitly set.

    The progress bar draws only the filled portion; the unfilled track is transparent. It therefore matches the same cell's normal, selected, or hovered background and stays consistent with neighboring cells. color changes only the filled portion.

    Progress text uses the cell's ForegroundRole (role 9) when available, otherwise the view's default text color. Selection and hover do not change the progress text color.

    Button Style¶

    {
  "data_type": "list",
  "render_type": "button",
  "value_list": ["Pending", "Approved", "Rework"]
}

    The button only changes the appearance. Selection, double-click editing, and multi-row editing behave exactly like a normal cell. It also supports color, suffix, and text_format.

    The button reads colors from the cell first:

    • BackgroundRole (role 8) becomes the button background.
    • ForegroundRole (role 9) becomes the button text color.
    • In button mode, role 8 is not painted across the entire cell. The rest of the cell keeps its default, selected, or hovered background.
    • If only a background is set, black or white text is chosen automatically for contrast.
    • If the cell has no background, app_args["color"] can provide a default button color.

    For example:

    item.set_data({
    8: [0.2, 0.33, 0.67],  # button background
    9: [1.0, 0.88, 0.4],   # button text
})

    Add a New Renderer¶

    For developers: renderers live in xpm_extend.cell_renderers. Implement and register a CellRenderer:

    from Qt import QtCore, QtGui
from xpm_extend.cell_renderers import CellRenderer, register_cell_renderer


class TagRenderer(CellRenderer):
    render_type = "tag"

    def paint(self, view, painter, option, index, args):
        text = str(index.data(QtCore.Qt.DisplayRole))
        painter.fillRect(option.rect.adjusted(4, 4, -4, -4),
                         QtGui.QColor("#4488cc"))
        painter.setPen(QtGui.QColor("white"))
        painter.drawText(option.rect, QtCore.Qt.AlignCenter, text)


register_cell_renderer("tag", TagRenderer())

    In this example, the choose items column offers aaa, bbb, and ccc:

    The drop-down automatically expands to fit the longest option text and icon instead of eliding content to match a narrow cell:

    • When the options fit, the popup has exactly the same width as the cell and does not overhang it.
    • When content is longer, the popup expands to the right from the cell's left edge. The popup and icon column stay aligned with the cell start.
    • Its width is limited by the available screen width. Long option lists remain scrollable; an individual option wider than the screen uses a horizontal scrollbar.

    Dictionary Options with Icons¶

    value_list is not limited to strings. Each option can be a complete set_data dictionary, or it can separate the label from the data. On commit, the editor calls item.set_data() for each target row, so custom icon painting through role 311, display text, colors, and other roles are applied together.

    A direct role dictionary:

    {
  "data_type": "list",
  "value_list": [
    {"0": "Circle", "311": [1, [[1, 0, 0], 20]]},
    {"0": "Blue square", "311": [0, [[0, 0, 1], 20, 20]]}
  ]
}

    The label + data form is also supported:

    {
  "label": "Circle",
  "data": {
    "0": "Circle",
    "311": [1, [[1, 0, 0], 20]]
  }
}

    label is shown in the drop-down, while data is passed unchanged to item.set_data(). If label is omitted, role 0 inside the data is used as the display text.

    Note

    app_args accepts both standard JSON and Python dictionary literals. Forms such as {0: "Done", 311: [...]} with unquoted numeric keys are also supported.

    Configuration¶

    The custom column's app_args can contain:

    {
  "data_type": "list",
  "value_list": ["aaa", "bbb", "ccc"]
}

    Numeric types also accept optional settings:

    {
  "data_type": "float",
  "min": 0,
  "max": 100,
  "step": 0.1,
  "decimals": 2
}

    Date and time types can use display_format to set the control's display format.

    Role keys in an option dictionary must be convertible to integers. Unrecognized roles remain in the data for the existing item.set_data implementation or another plugin to handle.

    Add a New Type¶

    For developers: the header metadata is available through hc.column_choose_menu.configer.datas['app_args']. The editor registry and input proxy live in xpm_extend.cell_editor_types and xpm_extend.cell_editor_delegate.

    Implement and register an EditorAdapter to add a type:

    from Qt import QtWidgets
from xpm_extend.cell_editor_types import EditorAdapter, register_editor_adapter


class ColorAdapter(EditorAdapter):
    data_type = "color"

    def create(self, parent, args, commit):
        return QtWidgets.QLineEdit(parent)

    def set_value(self, editor, value):
        editor.setText(str(value or ""))

    def value(self, editor):
        return editor.text()


register_editor_adapter("color", ColorAdapter())

    Unregistered data types automatically fall back to the original itemDelegate, so existing custom editors remain intact.
