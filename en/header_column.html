    Header Column Configuration¶

    The main view supports showing, hiding, reordering, and adding custom columns, as well as configuring column labels, cell arguments, and Python-computed values. Header actions are subject to the current account's user_level permission.

    Header Context Menu¶

    Right-click a column header to access:

    • Resize Column to Contents: resize only the current column.
    • Resize All Columns to Contents: recalculate every column width.
    • Sortable: enable or disable sorting for the current view; the setting is remembered.
    • Hide Current Column: remove the current column from the visible list.
    • Show All Hidden Columns: restore every hidden column.
    • Columns: expand the visibility menu; More at the end opens the full column manager.
    • Copy Column Identifier: copy the internal column key, such as user_yxc____7.
    • Add Column...: enter a display label and create a custom column with an automatic internal key.
    • Edit Column...: edit the current column's label, arguments, and Python function.
    • Expression...: legacy entry point. The current implementation only loads and prompts for the expression and does not reliably write it back; use app_args or a Python column function instead.

    Warning

    Hide Current Column only removes a column from the visible set. It does not delete the column configuration. Restore it from the Columns menu or the column manager.

    Column Manager¶

    Open Header context menu → Columns → More:

    Area or button Purpose
    Visible (显示的) Columns currently shown in the main view, in table order
    Hidden (隐藏的) Registered columns that are not currently shown
    + Create a custom column
    > Move selected visible columns to the hidden list
    < Move selected hidden columns back to the visible list
    ∧ / ∨ Reorder the selected visible column
    Double-click Open the detailed editor for that column

    Visibility and order are saved immediately. A newly created column usually starts in the hidden list and must be moved to the visible list before it appears in the main view.

    Detailed Editor Fields¶

    UI field Config key Purpose
    名字 (Label) labels Header display text; changing it does not change the internal column key
    sign header real_label Read-only internal key used by scripts and app_args
    参数 (Arguments) app_args String containing cell input settings
    apps app_type Optional usage/application identifier string
    Python python_command Python function that computes the column value for each row

    Note

    The current header implementation does not automatically filter columns by apps. Visibility is determined by the column manager; plugins and project scripts may interpret app_type themselves.

    OK saves only the current column. Cancel discards the edit.

    Cell Arguments app_args¶

    app_args selects the cell editor used when a cell is opened. Full formats and examples are in Custom Cell Input.

    The same app_args can use render_type to control how the cell is displayed:

    render_type Rendering
    progressbar Progress bar
    button Button style

    Editing and rendering are configured independently:

    {
  "data_type": "float",
  "render_type": "progressbar"
}

    Use max_height to limit the displayed height of a progress bar or button in taller rows; the control is vertically centered within the cell.

    For button, the cell's role 8 background becomes the button fill color and role 9 foreground becomes the text color. If no foreground is set, a high-contrast text color is selected automatically.

    Built-in types:

    data_type Input
    list Drop-down using value_list
    float / double Floating-point spin box
    int / integer Integer spin box
    datetime Date-time input
    date Date input
    time Time input

    Unconfigured or unregistered types fall back to the original itemDelegate.

    app_args accepts both standard JSON and Python dictionary literals. List options can carry full role data:

    {
    "data_type": "list",
    "value_list": [
        {0: "Done", 311: [1, [[0.5, 1, 0.5], 20]]},
        {0: "Waiting", 311: [1, [[0.5, 1, 1], 20]]},
    ],
}
    • 0 is the displayed cell text.
    • 311 is XP's existing custom icon-paint role.
    • The dictionary is passed to item.set_data(), so icon, color, and other roles apply together.

    Python-Computed Columns¶

    The Python field must define main(row) and return the value to display:

    def main(row):
    return row.item("root").text().split("_")[0]

    The function above extracts a sequence from the name. It can also read other cells in the same row:

    def main(row):
    return "_".join(row.item("root").text().split("_")[:2])

    After saving, the column functions are recompiled and the related columns refresh. A custom column with a Python function is treated as a computed column and is not written back as a normal editable cell. Put manually entered values in a regular custom column and configure its cell editor through app_args.

    Configuration File¶

    Column configuration is stored per user and per view:

    <project root>/prefs/<view>/<username>__column.json

    Example for the xp_demo shot view:

    D:/share/apps/xp/1.3.2.0/project/xp_demo/prefs/shot/user_yxc__column.json

    Main structure:

    {
  "items": ["root", "icon", "name", "user_yxc____7"],
  "labels": {
    "user_yxc____7": "Solve Status"
  },
  "app_args": {
    "user_yxc____7": "{\"data_type\": \"list\", \"value_list\": [...]}"
  },
  "app_type": {},
  "python_command": {},
  "modify_user": {},
  "modify_time": {}
}
    • items controls which columns are visible and their order.
    • labels stores display labels.
    • Each app_args value is a string, not a directly embedded object.
    • python_command stores Python function source.
    • modify_user / modify_time record the last edit metadata for each column.

    Warning

    Prefer the UI. The running application uses its in-memory configuration; direct file edits may be overwritten by the next save unless the view is reloaded. Back up the file before editing it manually.

    Script API¶

    loader = xm.views.shot.loader()
config = loader.user_config

config.datas["labels"]["user_yxc____7"] = "Solve Status"
config.datas["app_args"]["user_yxc____7"] = app_args_text
config.datas["python_command"]["user_yxc____7"] = python_func_text
config.save_datas("user_yxc____7")

    save_datas(column_name) saves only data related to that column. save() writes all column data for the current user configuration.
